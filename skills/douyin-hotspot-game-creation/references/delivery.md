# 完整策划与腾讯交付

重点投入在这里：学习档案只提供游戏背景，正式文档必须围绕用户选中的视频完成重点拆解、游戏对照与原创方案，不复制一整份通用游戏学习报告凑篇幅。两种选题入口共同使用下述交付合同。

腾讯表格内容按任务组织：①选题与原片证据（来源/读取范围/视频实际内容）；②重点拆解（关键时间段、内容结构、表达作用、可借鉴点和局限）；③游戏对照与结合（原片要素、具体游戏事实或玩家情境、依据、成立条件及不适配处）；④可执行方案（脚本、镜头、字幕/声音、素材与制作条件）；⑤证据与未知项。遵循目标工作簿的既定子表分工，不能把所有任务塞入一个新子表。

当前标准工作簿使用四个子表：

| 子表 | 写入内容 |
| --- | --- |
| 创作总览 | A/B 链路、目标游戏、方式、交付状态、正文定位及拍摄时长等可读制作信息 |
| A游戏视频改编 | 游戏广场选中原片的完整拆解、游戏对照、原创文案、分镜和制作条件 |
| B热点联动策划 | 热点广场选中原片的完整拆解、游戏结合、原创文案、分镜和制作条件 |
| 来源与核验 | 实际来源链接、可读原片名称、抽帧与语音范围、字幕术语复核状况和事实边界 |

task/result/draft编号、哈希、机器状态和原始核验JSON只留本机，不写进用户表格。来源表用可读文件名、真实公开链接、简短的读取范围与必要限制；本地视频没有公开链接就留空。

按精确表名与实际表头匹配，不能猜测子表ID。先只读生成分表计划，展示目标、子表、起始行和完整待写内容，再确认写入。字段不符或同名冲突时停止。新目标缺少标准子表时，建表也须列入同一审批计划。

A模式保留原片读取范围、时间轴、结构作用、迁移条件及新的完整方案。B模式先说明事件/话题实际意义，结合代表视频说明观众关注点，再给游戏方向。默认视频；明确图文时独立设计首图、逐页主视觉/文案、推进和末页兑现。

每个方向给具体题目、切口、开头、完整原创台词或文案、分镜/页序、素材、声音/剪辑建议及结尾。不能用“发生冲突”“揭晓原因”等空任务代替关键对白。无对白作品不强加人物对话。

低中高按真实投入和观看收益划分：低档已有素材即可独立表达；中档增加定向录制、比较或第二视角；高档可增加研究、实测或多人叙事。稀有资产/人员/素材未确认时写清前提，不宣称立即可拍。不保证流量和未经实测工时。

写入前确定腾讯在线表格file_id、URL、方案版本、完整正文hash及分表计划hash；配置和令牌不入仓库。同一路线后续任务在对应子表内追加独立区块，保存真实子表ID与行范围，已有用户内容不覆盖。只允许在另有明确授权、且旧值逐格匹配的特定占位行更新状态，不能放开通用非空覆盖。发生不明部分写入时先只读回查，不重复请求；部分完成不是整单完成，也不能自动重新建表掩盖失败。

原片、游戏参考作品、互联网资料分列。搜索入口不是原片，不静默删掉长文或多条引用。正文微软雅黑、换行顶端对齐，低中高用浅绿/蓝/橙并保留文字；不擅改既有冻结状态。

正文、URL内容、可点击超链接、样式分别验收。腾讯适配器先逐格回读正文，再通过MCP导出XLSX检查链接与字体、换行、分档颜色；导出或属性验证失败时保留分项警告。导出检查不是屏幕视觉验收，当前仍需真实账户跑通。完成提示必须保留这些差异。
