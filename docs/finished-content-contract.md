# 腾讯交付：分析之外，必须有实际成片内容

这次问题不是表格少一段说明，而是交付停留在导演建议：告诉创作者“加条件卡”“安排回应”“制造反转”，却让对方再写一遍真正的文字和剧情。文档写入成功、台词存在或基本可拍，都不足以证明核心内容已经交付。

A/B子表保留前四列分析与制作说明，增加第五列 **模拟成片内容（可直接使用）**。新列展示一个完整的模拟成片版本；不是影片已生成的证明。

## 第五列实际交付什么

| 项目 | 不充分的指导 | 应交付的具体内容 |
| --- | --- | --- |
| 口播／对白 | 加一句制造悬念的话 | 逐字的旁白或“角色：台词”；无口播明确写出 |
| 字幕／卡片 | 加一张资格卡 | 卡片标题、每一行文字及演示值；虚构案例明确说明 |
| 人物反应 | 队友指出错误 | 队友具体说什么，主角随后说什么、做什么 |
| 反转 | 结尾揭晓原因 | 原因及揭晓画面本身，例如音频文件名、录音全部内容、角色回答 |
| 画面 | 加入游戏元素 | 已读素材的具体对象、取景和先后变化，不能只换游戏名 |
| 时间 | 开场／中段／结尾 | 每镜镜号和起止秒位；图文则为明确页序 |
| 声音 | 配合适BGM | 新录台词、确定的声音安排；不需要音乐时直接写无音乐 |

完整脚本行同时给出全篇最终串词，逐镜格给出该镜实际台词、逐字屏幕文案和成片画面。片外的待拍素材列入素材清单，不能把待写对白、空反转或未确定规则藏进成片格。模拟例子不冒充用户真实账号或实战结果。

分析列可以解释为什么这样创作；成片列应直接呈现观众将听见、看见的内容。只有作品本身就是教程时，面向观众的教学口播才合理；不能把所有类型都写成教人如何剪辑。一个明确选择的成片版本优于多个让创作者自行拼凑的建议。

## 检查方式

1. 暂时遮住前四列。创作者只看第五列，应能录旁白、排字幕、制作道具并按镜头拼接，核心文字不需要自己再写。
2. 检查每张卡、每条消息、每段录音、每个结尾揭晓是否有完整内容；有意留给观众填写的工具表与创作者未写完的脚本要区分。
3. 检查具体游戏对象是否决定内容；不能以泛用社交对话或更换游戏名代替游戏结合。
4. 完整串词与每镜内容一致，镜号和时间可对应；对话、手势、道具前后状态和预录音清单闭合。
5. 原片观察、作者说法、假设案例、原创虚构分开；不能为了写得具体就补造游戏机制、真实战果或当前资格。
6. 腾讯写后回读第五列全文，同时确认原列、其他子表及原链接未被误改；内容审阅与远端保存验证分别报告。

结构检查只能确认字段和绑定，不能自动识别一段话究竟是有效成片还是措辞完整的空建议。仍需按上述问题做内容复核，用户审阅不能由模型自评代替。

## 兼容范围

新候选专用每镜字段为 `production_content:{spoken_words,screen_words,visual_content}`，不改遗留全局planSchema；input/receipt记录 `production-content-1`。新draft为五列，来源和内部读取数据继续留来源表或本机。

历史四列稿及冻结计划不自动改写。已升级五列表允许旧四列稿只写A:D，不擦除E。五列稿遇到仍为四列的目标表，只读准备会要求明确新增第五列表头后再核对；不在准备阶段偷偷升级用户表头。新建A/B子表的五列表头随审批计划冻结。相同旧输入仍可能复用旧四列任务，不把缓存结果冒充新合同生成，也不自动重跑模型。

当前用户四份模拟成片列采用人工逐行创作与独立复核，不追认此前自动稿已通过。新schema和代码回归通过不能代表新宿主自动成稿质量已经验收。

## 本轮实际改动与验证范围

用户两份已授权工作簿的A/B正文表，各增加E列，四表合计100格（含4个表头）。96格正文围绕43个固定镜头，分别提供全篇串词、逐镜成品、屏幕和道具全文、录音内容与素材定位；镜头规划为100／45／150／60秒。原分析列保留供对照，新增列是本次模拟成片版本。

这轮没有重跑原自动稿或将其质量改成通过，也没有调用红狐付费搜索/解析或下载模型。人工稿依据真实已读素材与明确的原创情境写作；姓名案例不冒充真实账号，图像不同对象不连接成同一舰船的实录。两路独立复核针对“只拿新列是否还缺核心内容”发现具体问题并在写前修订，不能把此结论扩大到用户已接受作品。

代码回归996项：973通过、0失败、23项既有固定门禁跳过；179个JS/Skill引用及2项合成XLSX检查通过。实际运行服务重启后旧四列候选仍可读取；另对真实已升级工作簿做只读准备，识别A/B五列表头，保持旧候选四列范围，远端变更0、Host调用0。该准备测试不批准或写入旧的未通过自动稿。

最终真实远端验证：两份工作簿所有原单元格与新增E列逐格一致；另导出两份XLSX，确认四张表E共100格全文、微软雅黑、换行和顶端对齐，原有超链接全部保持。中途一次只读导出请求超时，仅重新取得导出，没有重写内容。保存和导出通过不等于真人试读、成片或用户接受。
