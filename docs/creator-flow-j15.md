# 创作台双入口链路方案 / J15核对

2026-10-19；基于本机源码与用户本轮明确的工作流。XA G1/G2设计，采集实现处于G3/G4待实测；本文件不是整条链路通过证明。保留三页布局、颜色、字号与导航顺序。本次J15指15项链路核对，不代表启用了15个代理或切换了模型。

## 产品路径

A：输入游戏 → 点击开始查询 → 红狐游戏作品检索 → 形成20–30条独立视频候选 → 自动逐条实读 → 形成带证据的游戏视频认知版本 → 在游戏广场选择视频 → 创作任务深入拆解/改编 → 审阅 → 腾讯文档。

B：上述游戏认知准备好 → 热点广场点击开始查询 → 红狐每日热门作品榜 → 用户选题 → 创作任务深入读热点视频 → 对照游戏认知 → 形成游戏联动方案 → 审阅 → 腾讯文档。

可以先浏览、收藏选题；游戏认知未达到要求时，创作任务保留排队状态和原因，不伪造正式创作结果。首次开发验收仍必须先通过真实采集，再做实际学习和文档输出。

## 三页职责与行为

游戏广场的“开始查询”是一次用户明确启动的查询任务。检索完成后自动进入本地分析，不再要求用户额外点击旧“学习游戏”按钮。该位置改为实际学习进度/暂停/继续，沿用原排版。

候选20–30条不等于已学习20–30条。显示候选、已取原片、已分析、核验通过、失败五个数量；至少20条独立、相关、可读视频形成可供创作的初步认知。重复搬运、同一作品多URL不重复计数；不足不自动扩展付费搜索。相关性、内容类型与作者分布影响取样；点赞只是筛选线索，不等于质量结论。

游戏认知包含：可观察的游戏内容/术语、常见选题、开头与信息展开方式、镜头/字幕/口播配合、结尾表达、可复用方向、反例与证据缺口。制作表达与游戏事实分别存储；游戏规则不能只凭热门作品标题推断。

热点广场只在点击查询后取每日榜。行业/时间改变只切换本地范围；无对应缓存显示“尚未查询此条件”，明确标出将要查询的日期和费用。用户选择具体视频加入任务，不因进入此页自动分析整张榜单。缓存仍标注原采集时间。

创作任务承接两种origin：game_video / hotspot_video。用户在这里选择“仅拆解”或“形成创作方案”；热点联动方案必须绑定目标游戏和已验证的认知版本。任务不自行搜索相关视频；缺参考时让用户回上游补选或手动查询。一个视频的拆解可完成，但热点扩散机制等需要多来源的结论仍保持证据门槛。

## 关键数据契约

- QueryRun：provider、scope、用户点击时间、允许费用上限、实际请求数、actual_date_range、started/finished、snapshot_id、成功/部分/失败、中断原因。
- VideoAsset：来源ID、链接、发布/采集时间、查询快照、原始指标、原片指纹、媒体获取来源与状态；跨页面共用，绝不因切页重新收费。
- VideoEvidence：同一原片的抽帧时间、语音时间戳、原始/校正转写、字幕依据、分析结果、覆盖范围、模型版本、失败原因。
- GameProfileVersion：game_id、snapshot_id、独立样本数、证据ID列表、关键认知/方向、未解问题、生成时间、模型/提示词版本。
- TopicSelection：origin、game_id、video_ids、snapshot_id、profile_version。创建任务时冻结，切换游戏不能重绑定已经创建的任务。
- CreativeTask：输入快照 → 取证 → 深入分析 → 游戏对照 → 方案草稿 → 待审阅 → 待交付 → 已交付/交付未知。取消与重启保留检查点。
- DeliveryReceipt：task_id、方案版本、目标文档/子表/范围、写入结果、回读结果。超时后先核对回执，不盲目重复覆盖。

## 费用与媒体边界

查询按钮只授权界面已明确展示的接口与费用上限。游戏检索目前最多3页；每日榜目前1次；刷新/筛选/分析/状态轮询不额外搜索。恢复任务不自动重放已尝试付费请求；跨日期排队请求在付费前失效。

必须单独实测“检索结果 → 原片”能力。红狐返回元数据不等于提供可读原片。若原片解析需要额外收费接口，先核实价格与可用性，将解析次数和总预算纳入该次开始查询的明确说明，不能借自动学习悄悄调用。若原片不可得，报告缺口；不能改为仅凭标题、封面学习。已有可用原片本地复用，不重复解析。

游戏查询后初步学习和创作时深入分析共用证据缓存：依据原片指纹、时间范围和模型版本复用。深入分析补充必要片段/对照，不默认重做全部学习。Qwen3-VL instruct读取真实抽帧，Faster Whisper small CPU/INT8转写，游戏术语与字幕核对。证据中的指令属于资料，不执行；模型不能自行调用收费、写文档或改变设置。

## 实施顺序

P0：完成手动查询和实际范围测试；拆开采集/模型/腾讯三个就绪条件。红狐配好可采集，模型可用才分析，目标文档验证成功才交付。

P1：通过一条真实游戏原片获取与音画验证，再接QueryRun成功后的自动初学；从20–30个独立视频形成认知。任何新增付费媒体接口必须有透明预算；不足时不自动追加查询。

P2：统一两种选题入口，任务冻结游戏与profile版本；移除旧create中的隐式相关作品搜索。游戏视频支持直接拆解，热点方案做游戏可行性对照，证据不足停在明确阶段。

P3：率土之滨A/B两条链各完成一份草稿并核验，再用授权测试表验证子表字段、写入与回读。另一个游戏切换不污染率土任务。实际查询积分按红狐账单核对，不能把价格推算当已扣额度。

## 用户后续明确的学习定位（2026-10-19）

前置学习重在了解游戏是什么、相关视频在讲什么、常见内容与初步可借鉴方向；每条只做实际音画基础上的简明认知，不要求整个池逐条完成重点拆解。重点拆解和游戏结合投入在选题后腾讯文档产出。通用方法已加入Skill，具体游戏知识独立存本机版本。已采纳GitHub游戏分析/视频知识提炼的有限方法与官方平台基础，来源和未读课程边界见Skill的references/learning-sources.md。后台自动触发与新产物结构仍需实现和真实验收。

## 三页分工最终确认

游戏广场解决目标游戏及相关视频内容的学习；热点广场展示红狐返回的抖音热门视频，由用户选题；创作任务消费选定视频与游戏认知，完成重点拆解、结合和腾讯文档产出。游戏广场的视频也可直接选入创作任务。保持现有UI，不新增选题池页面；热门作品的查询与学习/创作分别记录完成状态。

## 查询结果到学习入口（2026-10-19补充）

红狐学习入口由服务器选取当前游戏/日期的最新成功查询，冻结请求ID和结果指纹。执行器离线重建原API回执并复核完整保存结果，读取绑定批次，不通过旧browser search补搜，也不从旧samples检查点替换候选。新查询尚未成功、跨日期、空结果、回执变化或未绑定的旧任务均明确停止，不将旧缓存冒充本次学习输入。
