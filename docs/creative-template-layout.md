# 腾讯文档四子表布局合同

交付时先读取用户指定在线表格的实际子表和字段，形成可审阅的确定性计划。详细视频分析不因布局调整而再次运行。主文直接消费固定候选的完整 `draft`，不会只写概览或让模型再拼一遍。

| 标准子表 | 字段 | 用途 |
| --- | --- | --- |
| 创作总览 | 链路、目标游戏、创作方式、当前状态、内容交付、来源核验、备注 | 索引和当前这次交付范围，不冒充视频成片发布或游戏机制已核实 |
| A游戏视频改编 | 策划环节、完整创作内容、游戏结合与素材、制作说明、模拟成片内容（可直接使用） | A 路线完整稿件 |
| B热点联动策划 | 同上 | B 路线完整稿件 |
| 来源与核验 | 来源ID、目标游戏、用途、原片链接、媒体状态、抽帧范围、语音状态、字幕术语复核、事实边界 | 来源与真实读取边界，网页不能标成已读音画 |

子表按精确名称和表头查找，不绑定开发者测试表格的 ID。已有子表保持原内容，只在明确空白的区域追加；模板缺表时在计划中列出待建子表，确认后才建立。错表头、同名歧义或准备后被编辑均应停止，不能猜列或覆盖。

新交付使用独立 `template-delivery` 记录，绑定任务、来源、认知版本、完整稿件hash、目标、分表计划hash、各区块和写前快照。只读准备不建表不写内容；显式批准精确计划后才写入。原“候选-…”专用子表交付记录保留历史，其授权不能迁移成分表授权。

先写正文与来源并全文回读，再更新本次总览。所有变更请求发出前落盘 pending；未知结果停止，不重复写。读取状态、刷新和重启不会触发推理、收费查询或腾讯写入。重复批准返回原记录，不产生第二份内容。只读对账可验证当前远端快照，不能修补它。

文本、URL显示文字、实际超链接目标和样式分别记录。追加区域的导出检查必须使用真实行偏移，不能从工作表第一行比较后宣称验证了后面的区块。腾讯富文本返回默认数字、布尔和空公式字段时按明确文本类型处理，真实公式、数值、错链或冲突依旧拒绝。

多表接口不提供远端事务锁；部分成功要逐表报告。读回只能证明当次快照，不能保证用户以后没有改动。具体开放状态看 `/api/quality-policy`，源码存在不代表本次真实交付已验收。

新增第五列的内容标准与四列历史兼容见[模拟成片合同](finished-content-contract.md)。第五列提供最终完整串词和逐镜的真实成片文字、画面、镜号时间；不以增加一列空的制作指导算完成。旧冻结计划不热升级。
